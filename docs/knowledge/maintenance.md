# 知识维护规范

适用范围：仓库内的 Markdown 知识库、Agent 入门说明、Skills、Hooks 与 Evals。当前为人工维护流程，不是已实现的 Memory 服务。

## 知识来源与可信度

优先使用：当前源码与锁文件 → 对应提交的实际运行/CI 证据 → 当前操作文档 → 目标设计与历史记录。代码能证明实现存在，只有实际运行能证明指定环境下有效；模型总结只能作为待核对材料。

知识条目应写明核对日期、来源路径/提交、适用范围、已知限制及验证方式。不能保存 API Key、Token、私钥、服务器秘密或环境专属凭据。避免复制完整日志，保留必要的脱敏结果与命令。

## 候选到发布

1. **候选**：从真实问题、测试失败、审查或事故中提取可复用规则，带来源与证据。
2. **核对**：与当前代码、测试和既有文档对照，检查冲突与适用项目；不能把另一个仓库的类名/配置视为本仓库实现。
3. **落位**：操作说明进运行指南；模块事实进代码索引/架构；建议性经验进 Skill；必须强制的规则实现为 Hook/网关检查并添加必要回归。
4. **审查发布**：随开发分支 diff 审查，按仓库流程提交/PR；写入文档不代表运行时已加载。
5. **失效维护**：接口、配置、路径、依赖或边界改变时同步更新当前说明；历史证据加历史标记并保留，不覆盖成新的实测结论。

## 变更对应文档

| 代码变化 | 同步维护 |
|---|---|
| 产品入口、支持模式、整体技术栈 | 根 README、当前实现、AGENT.md |
| 状态、审批、API、恢复契约 | 核心流程、Agent Core、运行指南 |
| 新配置/默认值/CLI 参数 | 包 README、运行指南；默认值以代码为准 |
| 依赖、脚本、CI、验证方式 | 开发指南、相关 workspace README |
| 沙箱、凭据、权限、数据存储 | Tool Kit、架构、安全现状与运行指南 |
| 文件移动/新模块/新资料 | 代码索引与 `docs/README.md` 导航 |
| 真实模型/服务器实测 | 带日期、提交和结果的验证记录，不仅修改完成复选框 |

## 合入前自查

- 命令与根 scripts、CLI allowedOptions 对齐；路径和相对链接存在。
- 已实现、模拟验证、真实验收、未来计划明确分开。
- 当前页不与历史日志中的旧状态混用；不重复维护多份完整状态表。
- 未声称自动知识注入、SSE、项目 CRUD、多用户认证等尚未实现能力。
- 记录实际跑过的检查及跳过项；不按固定测试数量推断功能完整。

`AGENT.md` 保持新人入门页，`AGENTS.md` 是跨工具入口，两者避免复制大段知识。详细规范链接到本知识库。未来实现检索与候选知识服务后，再以真实评测更新此流程。
