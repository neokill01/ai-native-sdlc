# 成熟度阶梯 / Adoption Ladder

这套方法论不必一次到位（原文：可从任意"没有箭头指入的 play"开始）。把落地切成台阶，**每个台阶都能独立带来价值、且不破坏现有流程**。这里定义的台阶顺序正是本仓库的实现顺序。

> 判断标准：**守住产物链 `intent → spec → plan（→ 代码+测试 → PR）→ 事故 → 回环`，人只在门禁上把关。**

---

## 台阶 0 · 骨架与约定（本轮）

- **交付物**：仓库骨架、`docs/playbook.md`（适配版方法论）、六份产物模板（`artifacts/*.template`）。
- **价值**：把"先想清楚再动手"变成可执行、可复用的约定。
- **入口**：`bin/new-intent "<一句话>"`（未做，见台阶 4 前的 `bin/`）。

## 台阶 1 · 用一个自包含案例走通前半段（规划→设计→构建→测试）

- **交付物**：用一个**自包含、可运行**的案例（炒股专家·开市前简报）产出一套完整示例 `intent.md` → `spec.md` → `plan.md` →（代码 + 测试），放进 `../examples/premarket-brief/`。
- **价值**：验证"适合自己的工程"不是纸上谈兵；案例不依赖外部仓库/密钥，纯标准库可一键运行，天然适合 git 展示与评审。
- **建议**：选一个**边界清晰、单人、无鉴权**的需求；数据源用接口抽象（`Source`），内置确定性样例，保证可复现。

## 台阶 2 · 护栏落地（Skills + Hooks）

- **交付物**：`agents/skills/<name>/SKILL.md`（建议性机构知识，如 API 安全审查）+ `agents/hooks/<name>.sh`（确定性护栏，如发布门禁、受保护路径）。
- **价值**：**Skill 让违规变少见，Hooks 让违规几乎不可能**。机构知识开始"可执行化"。
- **规则**：`AGENT.md` 里犯两次的错，写进 skill；必须无条件执行的策略背后加 hook。

## 台阶 3 · 测试与闭环（Evals + CI 门禁 + 控制带）

- **交付物**：`evals/<task>.json`（20–50 个真实任务回归）、`.github/workflows/agent-evals.yml`、`infra/bands.yaml`、`incident.md` 模板落地。
- **价值**：把质量从一次性 QA 变成持续回归；监控控制带让 agent 能自主回环。
- **规则**：每个生产事故都变成一个 eval；3σ 只走受控路由（PR / 预批准 runbook）。

## 台阶 4 · 转译为 DSH 可复用工作台

- **交付物**：把产物/门禁转译成 DSH 的 **agent preset / Cordis 插件**（如"意图澄清""方案评审""代码审查""发布门禁"各成一个 preset 或 skill），形成可复用工作台。
- **价值**：这套方法变成你日常工作台的一部分（当前会话本身就是 DSH），换项目也复用。
- **注意**：改 DSH 的 `cordis.yml`/agent preset 需遵循 [editing-cordis-compositions](../../...) 等技能规则；本仓库的 `agents/` 与 DSH 预设可分开维护，用"何时适配"解耦。

---

## 该从哪里切入？

- 想立刻提效：**台阶 0+1**（先规划、再实现）。
- 想治理产出的 agent 代码：**台阶 2+3**（护栏 + 回归）。
- 想无人值守回环：**台阶 3+4**（控制带 + DSH 工作台）。

**最小可用闭环**：`intent.md → plan.md → (代码+测试) → PR 审查 → incident.md → 回写 intent.md` —— 即便只守这一条链，价值也已成立。
