# Agentic DevOS · 当前流程与接口

核对日期：2026-11-05｜实现基线：`acb54b1`。以 `packages/agent-core/index.js`、`loop.js`、`apps/api/server.js` 为准。旧 `/v1/*`、SSE、MemoryCandidate 接口仍未实现。

## 任务状态

```text
created → intent_review → spec_review → plan_review → queued → running → verifying → completed
                                                                   ↑          ↓
                                                                   └ repairing
running / verifying → paused → queued
queued / running / verifying / repairing → failed 或 cancelled（按转移规则）
paused → cancelled
```

只有当前阶段的产物哈希获得批准，才能进入下一阶段。产物只能在 created 或审批阶段编辑；修改上游会清除该阶段与下游审批及下游产物。状态写入校验版本并与事件一起提交。完整转移表见 `index.js` 的 `next`。

Loop 执行前持久化 `pending`，执行后记录 `finished`。恢复遇到 pending 会暂停，不自动重放；finished 直接进入验证。验证失败在修复预算内进入 repairing；deadline 与累计模型预算不会因重启重置。

## 核心对象与事件

- Task：`id`、`goal`、`status`、`version`、`artifacts`、`approvals`、`repairs/maxRepairs`、`verification`，运行后还可含 checkpoint、stopReason、deliverySummary。
- Artifact：`{content, hash}`；Approval：`{hash, actor, at}`，保存在任务快照并生成审批事件。
- Event：`sequence`、`task_id`、`type`、JSON `payload`；写入事件时附加 `occurredAt`。不是原草案中的通用 traceId/runId 协议。
- 租约与 Worktree 独立持久化；报告保存不可变历史快照。同一任务版本和事件序列可复用报告。

## 当前 HTTP API（仅 Mock 管理台）

`GET /api/session` 返回内存会话 token、固定 projects、mode 与 actor。其余 `/api/*` 请求都要求 `x-devos-token`；Host/Origin 也受限制。

| 方法 | 路径 | 请求/用途 |
|---|---|---|
| GET | `/api/tasks` | 管理台任务列表 |
| POST | `/api/tasks` | `{title, description, projectId}` |
| GET | `/api/tasks/:id` | 任务详情，含 projectId、active、mode、workspaceKind |
| GET | `/api/tasks/:id/events` | JSON 事件数组，无 SSE/分页 |
| GET | `/api/tasks/:id/report` | 当前报告 |
| POST | `/api/tasks/:id/artifact` | `{version, kind, content}`，仅编辑当前阶段 |
| POST | `/api/tasks/:id/approve` | `{version}`，actor 固定为 local-console |
| POST | `/api/tasks/:id/run` | `{version}`，启动/恢复 Mock job |
| POST | `/api/tasks/:id/cancel` | `{version}`，取消当前 job 或 queued/paused 任务 |
| POST | `/api/tasks/:id/resolve` | `{version, decision, evidence}`，人工核对 pending |

拒绝未知请求字段与过期版本；运行中 job 的 cancel 接受非负整数旧版本，以免页面轮询进度使取消失效。实际请求字段限制和错误码见 `server.js`，不可向客户端开放本地路径、任意命令或模型凭据。

## CLI 与真实执行计划

CLI 提供 `create/artifact/approve/status/report/resolve/run`，参数见 `npm run devos -- help` 和 [Agent Core](../../packages/agent-core/README.md)。CLI 产物由操作者提交，不自动生成需求与规格。

真实模型任务的 plan 必须是 JSON，供独立验证器读取：

```json
{
  "verification": {
    "commands": [
      {"name": "unit", "command": ["npm", "test"], "timeout_ms": 120000}
    ]
  }
}
```

命令须能在预先准备、默认无网络的沙箱镜像中运行。网页 Mock 的 plan 使用固定 steps，不遵循此真实执行契约，也不会转为真实模型运行。

## 工具、报告与恢复

Responses Runtime 提供 `list_files/read_file/write_file/run_command`；文件受工作区、敏感路径与租约检查约束，命令是参数数组并在 DockerSandbox 运行。模型工具没有 approve/resolve 能力。

报告区分任务 status、编排 verification、真实命令 checks；未执行检查为 `not_run`，业务 `acceptance` 为 `needs_human_review`。原始命令输出不落库，保留退出码、耗时、信号、哈希和历史工具记录。

`resolvePending(id, version, {actor, decision, evidence})` 接受 `completed` 或 `not_executed`，只保存核对证据哈希。必须先检查实际工作区及外部副作用，等待旧租约失效；不能因“不确定”就选择重试。恢复步骤见[运行指南](../knowledge/operations.md)。

错误与预算状态并非草案中的自动退避系统；Loop 会停止并保留报告，未知模型用量拒绝自动继续。没有后台自动重试/恢复调度。
