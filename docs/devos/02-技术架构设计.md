# Agentic DevOS · 当前架构与演进方向

核对日期：2026-11-05｜实现基线：`acb54b1`。本页区分当前实现与未来设计；最初的 Next.js/NestJS/PostgreSQL 组合未被采用。

## 当前依赖与执行路径

```text
React 管理台 → Node HTTP API → TaskStore / runTask → 固定 Mock Runtime
                                            └→ WorkspaceTools → 固定 Node 断言
CLI → TaskStore / runTask → GitWorktreeManager → Responses Runtime
                                            ├→ WorkspaceTools：文件工具
                                            └→ DockerSandbox：模型命令与计划验证
TaskStore → SQLite：任务、事件、租约、Worktree、报告
```

网页与 CLI 复用领域核心，但不是同一执行入口：网页仅操作独立样例目录；CLI 才接入业务 Git Worktree、模型与 Docker。两者默认数据库不同，网页仅列出带 `console_meta` 的管理台任务。

## 代码模块

| 模块 | 职责 |
|---|---|
| `apps/console/src/main.tsx` | 页面、筛选、任务创建/详情、产物编辑审批、轮询、报告下载 |
| `apps/api/server.js` | 固定项目、HTTP Host/Origin/会话检查、版本校验、Mock job 生命周期 |
| `packages/agent-core/index.js` | TaskStore、状态/产物/审批与事件事务 |
| `loop.js`、`leases.js` | 执行/验证/修复、deadline、取消、独占租约与 fencing |
| `worktrees.js` | Git Worktree 创建、保留、清理与中断核对 |
| `openai-runtime.js`、`providers.js` | Responses 工具循环、独立计划验证、供应商配置 |
| `model-budget.js`、`evidence.js` | 跨修复/重启累计预算、元数据与报告快照 |

核心/API 使用 Node 24 JavaScript 和内置模块；前端为 React 19 + TypeScript 严格检查 + Vite 8。npm workspaces 与根 lockfile 管理依赖。

## 数据与信任边界

- TaskStore 保存任务 JSON 与版本，状态写入和事件在 SQLite 事务内完成；产物正文也保存在任务数据中，并非仅保存 Markdown 文件索引。
- 每个任务使用独占租约与递增 fencing token；只对同一 SQLite 数据库提供互斥，不是跨主机分布式锁。
- 文件工具在宿主侧做路径、内容及租约检查；命令在 Docker 中执行。路径检查不能替代 OS 隔离，也不能消除并发恶意进程造成的竞态。
- 宿主持有供应商密钥，不传入模型任务上下文或容器环境。Docker daemon、镜像及宿主 OS 是可信基础。
- 命令/验证正文不作为审计事件持久化，保存元数据与哈希；任务产物和经过检查的交付摘要仍可能含正文。SQLite 不是防篡改存储。
- Web 的随机会话 Token、Host/Origin 与 CSP 是本地单用户边界，不是多用户登录系统。

## 部署形态

本地单 Node 服务默认 `127.0.0.1:3001`，同时提供构建后的管理台与 API。私有服务器工作流使用独立 Node 24、systemd、`127.0.0.1:4317` 和 `/var/lib/agentic-devos` 持久数据，访问走 SSH 转发。见[部署文档](../devos-private-deployment.md)。

CI 使用 GitHub 托管 Ubuntu runner，覆盖 evals、核心/Python 门禁、Docker 隔离、前端构建/API/浏览器。工作流定义不能替代具体 run 的成功证据。

## 演进方向（尚未实现）

独立 Worker/队列、多用户认证与审批身份隔离、项目配置服务、代码/文档检索、候选经验审核、PR/Diff 交付。是否引入 PostgreSQL、Redis 或其他框架应以并发与运行需求为依据；当前没有这些依赖。

保留原则：产物链、批准计划后写入、独立验证、先单 Agent、知识带来源并经审核、PR 审查后交付。知识维护流程见[维护规范](../knowledge/maintenance.md)。
