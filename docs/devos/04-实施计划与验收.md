# Agentic DevOS · 实施路线图与验收 v1.0
状态：计划，非已完成结果

## P0：现状基线与工程准备
- 全量审查目录、脚本、CI、Skills/Hooks，建立资产清单。
- 明确 README 中“完成”的功能与可执行证据。
- 新建开发分支，禁止直接修改 main。
- 建立 Monorepo、格式检查、类型检查、测试框架。
**验收**：现有方法论文档未丢失；本地基础构建可复现；新旧 CI 兼容性明确。

## P1：单 Agent MVP
### Sprint 1：任务与产物
项目/任务 CRUD；状态机；intent/spec/plan 生成与人工门禁。
### Sprint 2：执行环境
- [x] Git Worktree：任务独立工作树、私有根目录、创建/删除恢复核对。
- [x] Worker 独占租约与 fencing；文件/命令工具边界租约校验。
- [x] pending 外部操作的人工核对与受审计恢复入口。
- [ ] OS Sandbox：当前 bwrap 在开发环境中因权限限制无法创建网络命名空间；不得用 Worktree 替代 OS 隔离。
- [x] 工具运行事件与工作树状态持久化。
### Sprint 3：Agent Loop
- [x] 确定性执行/验证/有限修复循环、取消与超时。
- [ ] 真实 Coding Harness/模型适配与真实任务评测。
- [ ] 费用/Token/时长预算与强制终止。
- [ ] 真实模型任务需在通过 OS Sandbox 验收后开放。
### Sprint 4：控制台与交付
任务详情、实时日志、Diff、验收报告、草稿 PR（若写权限已开通）。

**P1 验收用例**
1. 未批准 plan 时写文件被拒绝。
2. Agent 仅能修改任务工作区允许的文件。
3. 现有组件可被搜索并在任务中优先复用。
4. 故意引入 TS 错误时验证失败，修复后重新执行。
5. 达到迭代/时间预算时安全停止并留下报告。
6. 中途重启 Worker 后任务状态不丢失。
7. 测试未运行时报告显示 not_run。
8. 敏感密钥不进入日志或交付产物。
9. 失败任务不自动推送 main。
10. 全部任务保留可复查的证据链。

## P2：知识与记忆
- 代码/文档混合检索、符号索引、来源引用。
- 任务经验候选生成、冲突检测、审核发布。
- 对比知识增强前后的任务成功率与成本。
**验收**：有基线、有对照组，不能只凭主观感觉宣布提效。

## P3：协作与部署
- 引入专业 Agent（仅在单 Agent 瓶颈被量化后）。
- PR 审查分权；预发部署；生产审批与回滚演练。
**验收**：越权路径被阻止；部署与回滚有实际演练证据。
