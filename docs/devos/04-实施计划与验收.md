## 下一步优先级

1. **真实单任务闭环**：固定业务仓库提交和测试镜像；确认供应商、模型、价格与安全凭据；审批一个小任务，在 Docker 隔离下运行并审查 diff、报告和实际账单。
2. **真实任务评测**：至少 10 项可复现任务，保存输入、提交版本、验收命令、结果及人工判断；统计失败原因、修复次数、耗时和费用，不以 Mock 计入成功率。
3. **管理台接入真实执行**：显式区分 Mock/真实模式，补项目配置、Worktree/Diff、凭据与审批身份隔离；沿用领域核心的版本/租约/恢复约束。
4. **审查与交付**：受控分支推送、草稿 PR、独立审查；业务发布与管理台自身部署分开授权和验证。
5. **知识与记忆**：先证明检索/复用收益，再建设候选→审核→发布→过期流程与自动检索。

## P1 完成标准

- 未批准计划不能写业务代码，越界/敏感路径操作被拒绝。
- 实际模型在独立 Worktree 和经过验证的命令沙箱内完成任务。
- 原生项目测试真实执行；失败可有限修复，未运行明确标记。
- 超时、取消、重启与 pending 核对都有实际证据；旧 Worker 不能继续写入。
- 模型预算跨修复与重启累计，未知用量不自动重试。
- 至少 10 项真实任务结果可复查；需求验收由人工独立判断。
- 不泄露凭据，不自动合并/部署，保留审批和交付证据。

当前尚不满足完整 P1 完成标准。组件搜索、长期记忆、多 Agent、分布式 Worker 与业务生产发布闭环列入后续范围。

历史实施和过去 CI run 见[实施日志](07-implementation-progress.md)，不把早期阻塞自动沿用为当前事实。GitHub 权限、模型凭据、Docker daemon 和服务器状态均需在执行时验证。
