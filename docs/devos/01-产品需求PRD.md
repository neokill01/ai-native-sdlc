# Agentic DevOS · 产品需求文档 PRD v1.0
状态：待评审｜产品形态：Web Console + API + Worker + CLI（CLI 后续）

## 1. 产品目标
让个人开发者/小型研发团队把自然语言需求转化为可追踪的研发产物链，并在受控环境中自动执行编码、测试和修复。核心目标不是聊天，而是**可验证的任务完成**。

## 2. 用户与场景
- 项目负责人：导入仓库、配置规范、批准方案和 PR。
- 开发者：提交需求、观察 Agent 进度、处理阻塞、验收结果。
- 审核者：检查变更证据、风险和测试结果。
首个场景：对已有 React/Vue 项目增加一个边界明确的小功能，复用已有组件，运行项目原生校验命令，生成可审查的 Git Diff。

## 3. 功能需求
| ID | 优先级 | 功能 | 验收标准 |
|---|---|---|---|
| FR-01 | P0 | 仓库项目登记 | 保存 repo、branch、运行命令与项目规则 |
| FR-02 | P0 | 自然语言任务创建 | 创建 task，绑定项目及验收标准 |
| FR-03 | P0 | 意图/规格/计划产物 | 输出 intent/spec/plan，关联任务与版本 |
| FR-04 | P0 | 计划审批 | 未批准时不得进行写入型代码操作 |
| FR-05 | P0 | 隔离执行 | 每任务独立工作目录，防止串改 |
| FR-06 | P0 | 编码工具调用 | 支持读取、搜索、受限修改、diff |
| FR-07 | P0 | 验证与自动修复 | 运行 lint/typecheck/test；失败可有限重试 |
| FR-08 | P0 | 状态与日志 | 逐步展示执行状态、错误、耗时 |
| FR-09 | P0 | 交付报告 | 包含变更文件、测试证据、未解决问题 |
| FR-10 | P0 | 人工中断与恢复 | 审批等待可持久化，恢复后不重复危险操作 |
| FR-11 | P1 | GitHub PR 创建 | 审批后推送分支并创建草稿 PR |
| FR-12 | P1 | 项目上下文检索 | 优先复用已有工具/组件/约束 |
| FR-13 | P1 | 任务经验提取 | 经验先进入待审核队列 |
| FR-14 | P2 | 多 Agent 协作 | 分工清晰且结果可独立验证 |
| FR-15 | P2 | 部署与回滚 | 生产环境必须人工授权 |

## 4. 页面需求
**项目列表/详情**：项目创建、仓库地址、默认分支、命令与规则、最近任务。
**任务中心**：任务列表、过滤、创建、状态、失败原因。
**任务详情**：意图、计划、审批、步骤时间线、工具记录、测试输出、Diff。
**交付报告**：验收标准逐项结果、产物链接、风险提示、PR 入口。
**系统设置（P1）**：模型、成本预算、权限、策略、凭据管理（不回显密钥）。

## 5. 核心业务流程
提交目标→澄清/生成 intent→审核→spec→审核→plan→审批→创建隔离工作区→执行→验证→修复（有界）→审查→交付/草稿 PR→候选经验。

## 6. 非功能需求
- 所有工具调用具备 trace_id、task_id、耗时与脱敏日志。
- 运行中断后可恢复；外部写操作要求幂等键或执行前状态核查。
- 默认最小权限，拒绝访问工作区外文件、敏感路径和生产凭据。
- 每任务可配置时间、迭代、Token/费用上限。
- 未获得独立验证证据不得标记“已通过”。
- 不把模型推断当作事实；知识条目保留来源与版本。

## 7. MVP 不包含
复杂知识图谱、完整多 Agent 编排、生产自动部署、全自动合并主分支、复杂工作流画布。

## 8. MVP 完成定义
至少 10 个真实小任务构成评测集；每次执行保留完整证据；可以在隔离目录修改代码、验证、失败修复并输出交付报告；成功率如实统计，不预设通过。
